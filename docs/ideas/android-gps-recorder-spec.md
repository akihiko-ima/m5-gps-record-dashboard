# Android GPS レコーダー 仕様書

## 1. 目的

M5 GPS レコーダー（`docs/ideas/m5-recorder-spec.md`）と同じ役割を Android スマートフォンで実現する。
走行中の位置情報を一定間隔で取得して端末内に CSV で記録し、Web ダッシュボード（`docs/ideas/web-dashboard-spec.md`）で可視化する。

- M5 版は廃止せず、並行して運用する
- 出力する CSV の形式は M5 版と同じにし、Web 側の変換処理をそのまま使えるようにする

### M5 版との主な違い

| 観点             | M5 版                          | Android 版                                         |
| ---------------- | ------------------------------ | -------------------------------------------------- |
| 位置の取得       | GPS ユニット（NMEA を自前解析） | OS の位置情報 API（expo-location）                 |
| 記録媒体         | microSD `/tracks/`             | アプリ専用の内部ストレージ `tracks/`               |
| 操作             | 物理ボタン A / B / C           | 画面上のボタン                                     |
| 時刻             | GPS 時刻で本体の時計を同期     | 端末の時計（ネットワーク時刻で同期済み）をそのまま使う |
| 画面オフ時       | 常に動作                       | フォアグラウンドサービスで記録を継続               |
| Web への受け渡し | microSD を手動で取り出す       | 共有メニューでの書き出し / LAN 内での直接アップロード |

## 2. スコープ

### 対象

- 位置情報の取得（10秒間隔）
- 取得した位置情報の CSV への保存（M5 版と同じ形式）
- 画面上のボタンによる記録の開始・終了
- 画面オフ・バックグラウンドでの記録の継続
- 記録状態・測位状態の画面表示
- 保存済みファイルの一覧表示・削除
- CSV の書き出し（Android の共有メニュー）
- CSV の Web ダッシュボードへの直接アップロード（LAN 内）
- Web ダッシュボード側へのアップロード用 API（`POST /api/tracks`）の追加

### 対象外（スコープ外）

- iOS 対応（Expo のためビルドは可能だが、動作確認と最適化は Android のみとする）
- アプリ内での地図表示・軌跡表示（Web ダッシュボードで行う）
- 外出先（LAN 外）からのアップロード、認証
- クラウドへの自動バックアップ
- メーカー独自の省電力機能（バックグラウンドの強制停止）への対策（電池の最適化の除外の案内なども含めて行わない）

## 3. 技術構成

| 区分             | 採用技術                         | 用途                                                       |
| ---------------- | -------------------------------- | ---------------------------------------------------------- |
| フレームワーク   | Expo（SDK 57）+ React Native     |                                                            |
| 言語             | TypeScript                       |                                                            |
| 画面遷移         | Expo Router（`src/app/`）        |                                                            |
| 位置情報         | expo-location                    | フォアグラウンド / バックグラウンドでの位置の取得          |
| バックグラウンド | expo-task-manager                | バックグラウンドで位置を受け取るタスクの登録               |
| ファイル保存     | expo-file-system                 | CSV の作成・追記・一覧・削除                               |
| 書き出し         | expo-sharing                     | Android の共有メニューで CSV を渡す                        |
| ローカル保存     | AsyncStorage（@react-native-async-storage/async-storage） | アップロード先 URL・アップロード済みフラグ |
| ビルド           | 開発ビルド（expo-dev-client）    | バックグラウンド位置情報は Expo Go では動かないため        |

- `android/` は Continuous Native Generation で生成する。ネイティブ設定は `app.json` とプラグインで行い、`android/` を手で編集しない

### 必要な権限（Android）

| 権限                                    | 用途                                     |
| --------------------------------------- | ---------------------------------------- |
| `ACCESS_FINE_LOCATION`                  | 精度の高い位置情報の取得                 |
| `ACCESS_BACKGROUND_LOCATION`            | 画面オフ・バックグラウンドでの位置の取得 |
| `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_LOCATION` | 記録中の常駐通知（フォアグラウンドサービス） |
| `POST_NOTIFICATIONS`（Android 13 以降） | 常駐通知の表示                           |
| `INTERNET`                              | Web ダッシュボードへのアップロード       |

- 権限の要求は、初回の記録開始時に順番に行う（「アプリ使用中のみ」→「常に許可」）
- 「常に許可」が得られない場合は記録を開始せず、設定画面を開く案内を表示する

## 4. 機能要件

### A1: 位置情報の取得

- expo-location のバックグラウンド位置更新（`startLocationUpdatesAsync`）で位置を受け取る
  - 精度: 最高精度（`Accuracy.BestForNavigation` 相当）
  - 更新間隔: 10秒（`timeInterval: 10000`、`distanceInterval: 0`）
- OS が渡す更新間隔は前後するため、**記録の間隔はアプリ側で 10 秒ごとにそろえる**
  - 10 秒ごとの記録時点で、直近に受け取った位置を 1 行として書き込む
  - 直近の位置が古すぎる（20 秒以上前）場合は未測位として扱う
- 取得する項目（M5 版と同じ）:

  | 項目       | 取得元（expo-location）    | 変換                       |
  | ---------- | -------------------------- | -------------------------- |
  | 日時       | 記録時点の端末の時計（UTC） | ISO 8601 に整形            |
  | 緯度・経度 | `coords.latitude / longitude` | 小数 6 桁                 |
  | 高度       | `coords.altitude`          | m、小数 1 桁               |
  | 速度       | `coords.speed`             | m/s → km/h、小数 1 桁      |
  | 捕捉衛星数 | 取得できない               | 空欄（6 章を参照）         |
  | HDOP       | 取得できない               | 空欄（6 章を参照）         |

### A2: 位置情報の保存

- 記録中は、10 秒ごとに 1 行を CSV に追記する
- 記録の開始ごとに新しいファイルを作成する（1回の記録 = 1ファイル）
- 1 行ごとにファイルへ書き込み、アプリの強制終了でもそれまでの行が残るようにする
- 記録中に未測位（位置が得られない・古すぎる）になった場合も行は記録する
  - timestamp にはその時点の UTC を記録する
  - それ以外の列はすべて空欄とする（M5 版と同じ）

### A3: 記録の開始・終了

- 待機画面の「記録開始」ボタンで記録を開始する
  - 位置情報の権限がなければ要求する（3 章を参照）
  - 測位済み（直近 20 秒以内に位置を取得できている）であれば、新しいファイルを作成して記録を開始する
  - 未測位であれば記録を開始せず、「測位エラー」状態にしてメッセージを表示する
  - 測位エラー状態で「再試行」ボタンを押すと、再度記録開始を試みる
- 記録中画面の「記録終了」ボタンで記録を終了する
  - 誤操作を防ぐため、確認ダイアログを表示してから終了する
- 記録中は Android の常駐通知を表示する（「GPS 記録中」。文言は固定で、件数・経過時間はアプリの画面で確認する）
- 記録中はファイル一覧の操作（削除・アップロード）を無効にする
- アプリが OS に終了させられた後に再度開いた場合は、記録中のファイルを特定し、記録を再開するか終了するかを選べるようにする

### A4: 画面表示

- 現在の状態（待機中 / 測位エラー / 記録中）
- 測位状態（測位済み / 未測位）と位置の精度（`coords.accuracy`、m）
- 最新の緯度・経度
- 記録中は記録件数と経過時間
- 測位エラー時は「GPS 未測位のため記録を開始できません。屋外など上空の開けた場所で再試行してください」と表示する
- 権限の不足、ファイルの書き込みエラーはエラーとして表示する

### A5: 保存済みファイルの一覧表示

- 一覧画面に `tracks/` の CSV ファイルを表示する
- 表示項目: ファイル名（記録開始日時）、ファイルサイズ、記録件数、アップロード状態（A7 を参照）
- 表示順: 新しいものが上
- 一覧はスクロールで表示する（M5 版のページ送りは不要）
- ファイルが 1 件もない場合は「保存されたファイルはありません」と表示する
- 各ファイルの行に「書き出し」「アップロード」「削除」のボタンを表示する
  - 削除は確認ダイアログを表示してから行う

### A6: CSV の書き出し（共有メニュー）

- 一覧の「書き出し」を押すと、Android の共有メニュー（expo-sharing）を開く
- Google ドライブ・メール・Files などに CSV を渡し、PC から Web ダッシュボードのアップロード画面で取り込む
- MIME タイプは `text/csv`

### A7: Web ダッシュボードへの直接アップロード（LAN 内）

- 一覧の「アップロード」を押すと、走行種別（バイク / 自転車）を選ぶダイアログを表示する
  - 走行種別は必須（Web 側の仕様に合わせる）
- 選んだ種別と CSV を Web ダッシュボードの API に送信する
- 結果をトーストなどで通知する
- 自宅 LAN の HTTP サーバーに送るため、平文 HTTP 通信（cleartext traffic）を許可する
  - `app.json` の設定（expo-build-properties の `usesCleartextTraffic` など）で行い、`android/` は手で編集しない

#### アップロード先 URL の記憶

- アップロード先 URL（例: `http://192.168.1.10:3000`）は AsyncStorage に保存し、アプリを再起動しても覚えておく
- アップロード成功時に、使った URL を保存する。次回のアップロードダイアログでは、その URL を入力済みの状態で表示する
- 設定画面でも URL を確認・変更できる
- URL が未保存のときは、アップロードダイアログで URL の入力を必須とする

#### アップロード状態の表示

- ファイルごとのアップロード状態を AsyncStorage に保存する（キー: ファイル名、値: アップロード日時と送信先 URL）
- 一覧の各行に、アップロード状態をバッジで表示する

  | 状態           | 表示（例）                   | 条件                               |
  | -------------- | ---------------------------- | ---------------------------------- |
  | 未アップロード | 「未アップロード」（灰色）   | 保存された状態がない               |
  | アップロード済み | 「アップロード済み」（緑色） | アップロードに成功したことがある |
  | 失敗           | 「失敗」（赤色）             | 直近のアップロードが失敗した       |

- アップロード済みのファイルも再度アップロードを試せる（Web 側から削除した後に登録し直す場合など）
  - Web 側は同じ内容の CSV を重複として拒否する（`DUPLICATE`）。この応答を受けた場合は「登録済み」とみなし、アップロード済みにする
- ファイルを削除したときは、そのファイルのアップロード状態も削除する
- 書き出し（A6）はアップロード状態を変えない（Web 側に登録されたかを判断できないため）

#### Web 側に必要な変更

既存のアップロードは Server Action（`web/src/app/actions.ts` の `uploadTrack`）のため、アプリから呼べる API を追加する。

- `POST /api/tracks`（`multipart/form-data`）
  - `file`: CSV ファイル
  - `activityType`: `motorcycle` / `bicycle`
- 検証・変換・保存は既存の `uploadTrack` と同じ処理（`track-service`）を使う
- レスポンス: 成功時 `201` と登録したトラックの概要。失敗時はエラーコード（`TrackErrorCode`）とメッセージを返す（重複は `409`、サイズ超過は `413`、それ以外の入力エラーは `400`）
- 認証は行わない（Web 側と同じく自宅 LAN 内での利用を前提とする）

### A8: 設定

- アップロード先 URL（AsyncStorage に保存した値の確認・変更）

## 5. 画面構成と状態遷移

### 画面

| 画面         | ルート（案）          | 内容                                       |
| ------------ | --------------------- | ------------------------------------------ |
| 記録         | `src/app/index.tsx`   | 状態表示と記録開始・終了ボタン             |
| ファイル一覧 | `src/app/tracks.tsx`  | 保存済み CSV の一覧と書き出し・アップロード・削除 |
| 設定         | `src/app/settings.tsx` | アップロード先 URL など                   |

- 画面下部のタブで切り替える

### 記録画面の状態遷移

```
[起動] → [待機中] --記録開始(測位済み)--> [記録中] --記録終了(確認)--> [待機中]
             \                              |
              記録開始(未測位)               書き込み失敗
                ↓                            ↓
            [測位エラー] --再試行(測位済み)--> [記録中]
               (未測位なら測位エラーのまま)  [保存エラー]
```

| 現在の状態 | イベント           | 条件     | 次の状態                       |
| ---------- | ------------------ | -------- | ------------------------------ |
| 起動       | 初期化完了         | 記録中のファイルなし | 待機中               |
| 起動       | 初期化完了         | 記録中のファイルあり | 記録中（再開 / 終了を選択） |
| 待機中     | 記録開始           | 測位済み | 記録中                         |
| 待機中     | 記録開始           | 未測位   | 測位エラー                     |
| 測位エラー | 再試行             | 測位済み | 記録中                         |
| 測位エラー | 再試行             | 未測位   | 測位エラー（表示を継続）       |
| 記録中     | 記録終了（確認後） | -        | 待機中（記録を停止）           |
| 記録中     | 書き込み失敗       | -        | 保存エラー（記録を停止）       |

## 6. データ仕様

### ファイル配置・命名

- 保存先: アプリ専用の内部ストレージ（`Paths.document`）の `tracks/`
- ファイル名: `YYYYMMDD_HHMMSS.csv`（記録開始時刻、UTC）— M5 版と同じ

### ファイル形式（CSV）

M5 版と同じ列構成とする。

```csv
timestamp,latitude,longitude,altitude_m,speed_kmh,satellites,hdop
2026-10-11T01:23:40Z,35.658636,139.745407,12.3,42.5,,
2026-10-11T01:23:50Z,35.659302,139.746293,12.6,40.1,,
2026-10-11T01:24:00Z,,,,,,
```

- `satellites` と `hdop` は Android の位置情報 API から取得できないため、常に空欄とする
  - Web 側の CSV パーサー（`web/src/lib/track/csv.ts`）は空欄を `null` として受け付けるため、Web 側の修正は不要
- `altitude_m` / `speed_kmh` は端末が値を返さない場合（`null`）に空欄とする
- 文字コード: UTF-8、改行コード: LF、タイムスタンプは UTC

## 7. 非機能要件

- アプリが強制終了されても、それまでに書き込んだ行は失われないこと
- 画面オフのまま 3 時間程度の記録を継続できること（メーカー独自の省電力機能による停止はスコープ外）
- 電池消費を抑えるため、記録していない間は位置情報の取得を止めること
  - 待機画面では、画面表示中のみ測位状態の確認用に位置を取得する

## 8. 未決事項

- なし（省電力機能への対策はスコープ外、ローカル保存は AsyncStorage に決定）

# M5 GPSレコーダー 仕様書

## 1. 目的

M5Stack と GPS ユニットを使い、走行中の位置情報を一定間隔で取得して microSD カードに記録する。
記録したデータは後段のWebダッシュボードで可視化するための入力となる。

## 2. スコープ

### 対象（M5 が担う機能）

- GPS ユニットからの座標情報の取得（10秒間隔）
- 取得した座標情報の microSD への保存
- ボタンによる記録の開始・終了
- 記録状態・GPS 受信状態の画面表示
- 保存済みファイルの一覧表示

### 対象外（スコープ外）

- microSD からのデータ取り出し（ユーザーが手動で行う）
- Web へのアップロード（Web 側にアップロードページを設けて対応する）
- Wi-Fi / Bluetooth などによる通信機能

## 3. ハードウェア構成

| 部品     | 型番                      | 用途                                         |
| -------- | ------------------------- | -------------------------------------------- |
| 本体     | M5Stack Basic v2.7        | 制御・画面表示・ボタン入力・microSD スロット |
| GPS      | M5Stack用GPSユニット v1.1 | 位置情報の取得（UART 接続、115200bps）       |
| 記録媒体 | microSD 16GB              | GPS ログの保存（FAT32 フォーマット）         |

### 開発環境

- Arduino（M5Stack 用ライブラリを使用）

### GPS ユニットとの通信

- 方式: UART（NMEA センテンス）
- ボーレート: 115200bps
- 接続ポート: 本体側面の Grove ポート Port A（RX: GPIO22 / TX: GPIO21）
  - Port A は内部 I2C（電源 IC）と共用のため、内部 I2C を解放して UART として使う
  - Port C（M5GO ボトム、GPIO16 / GPIO17）に接続する場合は `GpsReader.cpp` のピン定数を変更する

## 4. 機能要件

### F1: GPS 座標の取得

- GPS ユニットから NMEA センテンスを受信し、座標情報を解析する
- **取得間隔: 10秒に1回**
- 取得する項目:
  - 日時（UTC。取得方法は F2 を参照）
  - 緯度・経度
  - 高度
  - 速度
  - 捕捉衛星数
  - HDOP（測位精度の目安）

### F2: GPS 情報の保存

- 記録中は、F1 で取得したデータを1件ずつ microSD に追記する
- 記録の開始ごとに新しいファイルを作成する（1回の記録 = 1ファイル）
- 電源断に備え、1件書き込むごとにファイルをフラッシュする
- 記録中に GPS が未測位（位置を捕捉できていない）になった場合も行は記録する
  - timestamp にはその時点の UTC を記録する
  - それ以外の GPS データの列はすべて空欄とする

#### 未測位時の UTC の取得方法

- M5Stack Basic には電池でバックアップされる時計（RTC）がないため、GPS の時刻を本体の時計に同期して使う
- 測位できている間は、GPS から取得した UTC で本体の時計を同期し続ける
- 未測位の間は、最後に同期した本体の時計から UTC を求めて timestamp に記録する
- 記録の開始には測位が必須のため（F3 参照）、記録中は必ず一度は同期済みの状態になる

### F3: ボタンによる記録の開始・終了

| ボタン  | 待機中                 | 測位エラー             | 記録中         | ファイル一覧         |
| ------- | ---------------------- | ---------------------- | -------------- | -------------------- |
| ボタンA | 記録開始を試みる       | 記録開始を再試行する   | 記録を終了する | （無効）             |
| ボタンB | ファイル一覧を表示する | ファイル一覧を表示する | （無効）       | 待機中に戻る         |
| ボタンC | （未割り当て）         | （未割り当て）         | （未割り当て） | 次のページを表示する |

- 記録を開始するには GPS が測位済みであることを条件とする
  - 測位済み: 新しいファイルを作成して記録を開始する
  - 未測位: 記録を開始せず、画面にエラーを表示して「測位エラー」状態に遷移する
- 測位エラー状態では、ユーザーが受信環境（屋外に出る・上空が開けた場所に移動するなど）を見直した後にボタンAを押すと、再度記録開始を試みる
  - 測位済みなら記録を開始し、未測位なら測位エラーのまま
- 記録中のファイル一覧表示は、誤操作による記録への影響を避けるため無効とする
- 記録終了時はファイルを確実にクローズする

### F4: 画面表示

- 現在の状態（待機中 / 測位エラー / 記録中 / ファイル一覧）
- GPS の測位状態（測位済み / 未測位）と捕捉衛星数
- 最新の緯度・経度
- 記録中は記録件数と経過時間
- 測位エラー時は「GPS 未測位のため記録を開始できません。受信環境を確認してボタンAを押してください」などのメッセージを表示する
- microSD の未挿入・書き込みエラー時はエラー表示

### F5: 保存済みファイルの一覧表示

- ボタンBを押すと、microSD の `/tracks/` にある CSV ファイルの一覧を画面に表示する
- 表示項目: ファイル名（記録開始日時）、ファイルサイズ
- 表示順: 新しいものが上
- 1画面に収まらない場合はボタンCで次のページを表示する（最終ページの次は先頭に戻る）
- ファイルが1件もない場合は「保存されたファイルはありません」と表示する
- ボタンBをもう一度押すと待機中に戻る

## 5. 状態遷移

```
[起動] → [待機中] --ボタンA(測位済み)--> [記録中] --ボタンA--> [待機中]
            |  \                          |
            |   ボタンA(未測位)            SD書き込み失敗
            |     ↓                        ↓
            |  [測位エラー] --ボタンA(測位済み)--> [記録中]
            |     |  (未測位なら測位エラーのまま)    [SDエラー]
            |     |
         ボタンB  ボタンB
            ↓     ↓
         [ファイル一覧] --ボタンB--> [待機中]
              ↺ ボタンC（次のページ）
```

| 現在の状態   | イベント        | 条件     | 次の状態                       |
| ------------ | --------------- | -------- | ------------------------------ |
| 起動         | 初期化完了      | -        | 待機中                         |
| 待機中       | ボタンA         | 測位済み | 記録中                         |
| 待機中       | ボタンA         | 未測位   | 測位エラー                     |
| 待機中       | ボタンB         | -        | ファイル一覧                   |
| 測位エラー   | ボタンA         | 測位済み | 記録中                         |
| 測位エラー   | ボタンA         | 未測位   | 測位エラー（エラー表示を継続） |
| 測位エラー   | ボタンB         | -        | ファイル一覧                   |
| 記録中       | ボタンA         | -        | 待機中（ファイルをクローズ）   |
| 記録中       | SD 書き込み失敗 | -        | SDエラー                       |
| ファイル一覧 | ボタンB         | -        | 待機中                         |
| ファイル一覧 | ボタンC         | -        | ファイル一覧（次のページ）     |

## 6. データ仕様

### ファイル配置・命名

- 保存先: `/tracks/`
- ファイル名: `YYYYMMDD_HHMMSS.csv`（記録開始時刻、UTC）

### ファイル形式（CSV）

```csv
timestamp,latitude,longitude,altitude_m,speed_kmh,satellites,hdop
2026-10-11T01:23:40Z,35.681236,139.767125,12.3,42.5,9,0.9
2026-10-11T01:23:50Z,35.681902,139.768011,12.6,40.1,9,0.9
2026-10-11T01:24:00Z,,,,,,
```

- 3行目は未測位時の例（timestamp のみ記録し、GPS データは空欄）

| 列名       | 型              | 説明                                               |
| ---------- | --------------- | -------------------------------------------------- |
| timestamp  | ISO 8601（UTC） | 記録時点の UTC（GPS と同期した本体の時計から取得） |
| latitude   | 小数（10進度）  | 緯度                                               |
| longitude  | 小数（10進度）  | 経度                                               |
| altitude_m | 小数            | 高度（m）                                          |
| speed_kmh  | 小数            | 速度（km/h）                                       |
| satellites | 整数            | 捕捉衛星数                                         |
| hdop       | 小数            | 水平精度低下率                                     |

- 文字コード: UTF-8、改行コード: LF
- タイムスタンプは UTC で保存する（表示時のタイムゾーン変換は Web 側で行う）
- Web 側のアップロード機能はこの形式を入力として想定する

### 保存形式に CSV を採用する理由

Web で Google マップに軌跡を重ねて表示することを想定し、他の形式と比較した。

| 形式    | 拡張子   | M5 での追記                        | 電源断への強さ                           | Google マップでの表示                  |
| ------- | -------- | ---------------------------------- | ---------------------------------------- | -------------------------------------- |
| CSV     | .csv     | 1行追記するだけ                    | 強い（途中までの行は有効）               | 変換が必要（Web 側で容易）             |
| GeoJSON | .geojson | 末尾の `]}` を毎回管理する必要あり | 弱い（閉じ括弧がないと JSON として不正） | Data レイヤーでそのまま読み込める      |
| GPX     | .gpx     | 閉じタグの管理が必要               | 弱い（閉じタグがないと XML として不正）  | 標準では非対応（変換が必要）           |
| KML     | .kml     | 閉じタグの管理が必要               | 弱い（閉じタグがないと XML として不正）  | KmlLayer は公開 URL のファイルのみ対応 |

- 記録装置の要件は「追記が簡単」「電源断でもデータが壊れない」ことであり、CSV が最も適している
- 表示に適した GeoJSON への変換は、アップロード時に Web 側で行う（CSV の1行 → 座標1点、空欄の行は除外）
- GPX はほかの地図アプリとの互換用に、必要になったら Web 側からエクスポートする

## 7. 非機能要件

- 電源断が発生しても、それまでに書き込んだデータは失われないこと
- 16GB の microSD で十分な期間の記録ができること
  （1件あたり約70バイト × 10秒間隔 ≒ 1時間あたり約25KB）

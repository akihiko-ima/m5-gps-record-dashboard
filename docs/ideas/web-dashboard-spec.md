# GPS 走行記録 Web ダッシュボード 仕様書

## 1. 目的

M5 GPS レコーダー（`docs/ideas/m5-recorder-spec.md`）が microSD に記録した CSV をブラウザからアップロードし、
地図上に走行軌跡として表示する Web ダッシュボードを作る。
自宅のサーバー（ミニ PC / Raspberry Pi など）で動かすことを前提とし、構成はできるだけ単純に保つ。

## 2. スコープ

### 対象

- ブラウザからの CSV アップロード（走行種別「バイク / 自転車」を選択）
- CSV から地図表示用の形式（GeoJSON）への変換と保存
- アップロード済みトラックの一覧表示（新しい順）
- 選択したトラックの軌跡を地図上に表示（走行種別ごとに色分け）
- 時間スライダーによる走行の再生
- 登録済みトラックの走行種別の変更
- トラックの削除

### 対象外（スコープ外）

- ユーザー認証（自宅 LAN 内での利用を前提とする）
- 複数ユーザー対応
- クラウドストレージ（S3 など）への保存 — ローカルの `data/` ディレクトリに保存する
- M5 からの直接アップロード（Wi-Fi 通信など）
- GPX / KML へのエクスポート（必要になったら追加する。6.4 参照）

## 3. 技術選定

### 3.1 フレームワークの比較

制約: TypeScript / React ベース / Tailwind CSS / shadcn/ui

| 観点                     | Next.js（App Router）                           | TanStack Start                               | React Router v7（Framework mode）       |
| ------------------------ | ----------------------------------------------- | -------------------------------------------- | --------------------------------------- |
| 成熟度・情報量           | 最も多い。トラブル時に情報が見つかりやすい      | 比較的新しく、情報量は少なめ                 | Remix の後継で実績あり                  |
| shadcn/ui の対応         | 公式の第一サポート対象（`shadcn init` で即導入） | 公式ガイドあり                               | 公式ガイドあり                          |
| サーバー処理の書き方     | Server Actions / Route Handlers                 | Server Functions（型安全で明快）             | loader / action                         |
| ファイル + SQLite の扱い | Node.js ランタイムでそのまま使える              | そのまま使える                               | そのまま使える                          |
| セルフホスト             | `output: "standalone"` で単体 Node サーバー化   | Vite ビルド → Node サーバー                  | Vite ビルド → Node サーバー             |
| 複雑さ                   | RSC / キャッシュの概念がやや多い                | 概念は少なくシンプル                         | 概念は少なくシンプル                    |

### 3.2 結論: Next.js（App Router）を採用する

- shadcn/ui・Tailwind CSS の導入手順が最も整っており、本プロジェクトの UI 制約と相性が良い
- 本アプリの規模（画面 1 つ + アップロード + 一覧/詳細取得）では、App Router の複雑な機能（ISR、Edge など）は使わずに済む
  - 使うのは「Server Component でのデータ取得」と「Server Action によるアップロード・削除」のみに絞る
- `output: "standalone"` により `node server.js` だけで起動でき、自宅サーバーへの配置が単純
- 情報量が多く、ハマったときに解決しやすい

> TanStack Start は設計としては簡潔で魅力的だが、情報量とエコシステムの成熟度を優先して今回は見送る。

### 3.4 地図タイルの利用条件（OSM タイル利用ポリシー）

地図ライブラリは **Leaflet + OpenStreetMap** に決定した（Google Maps は API キーと課金設定が必要で、自宅運用には過剰なため）。
背景地図には OpenStreetMap 財団（OSMF）の標準タイル `tile.openstreetmap.org` を使うため、
[Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) を守るよう、次のとおり実装する。

| ポリシーの要求                                   | 本アプリでの対応                                                                                         |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| タイル URL は `https://tile.openstreetmap.org/{z}/{x}/{y}.png` のみを使う（HTTP やほかのサブドメインは不可） | この URL を既定値とする。サブドメイン（`{s}`）付きの URL は使わない                                       |
| URL をハードコードしない（推奨）                 | 環境変数 `NEXT_PUBLIC_TILE_URL` で変更可能にする（既定値は上記 URL）                                     |
| 地図上に帰属表示を明示する（通常は右下、「© OpenStreetMap contributors」を著作権ページにリンク） | Leaflet の帰属表示（attribution control）を右下に常に表示する。文言は `© <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a> contributors` |
| 帰属表示を UI の下に隠したり、トグルで非表示にしたり、画面外に出したりしない | サマリーなどのオーバーレイは地図の右下に置かない。帰属表示を消す設定・CSS は入れない                     |
| Web アプリは Referer を送ること（Referer を止める Referrer-Policy は不可） | タイルはブラウザから直接取得する。`Referrer-Policy: no-referrer` は設定せず、Leaflet の `referrerPolicy` オプションも指定しない（ブラウザ既定の `strict-origin-when-cross-origin` のままにする） |
| キャッシュを迂回しない（`Cache-Control: no-cache` などを送らない）。キャッシュヘッダーに従う | ブラウザ標準のキャッシュに任せる（独自のキャッシュ無効化はしない）                                       |
| 一括ダウンロード・先読み（プリフェッチ）・オフライン保存は禁止 | 表示中の範囲のタイルだけを取得する。オフライン保存機能・広域の先読みは作らない。Leaflet の `keepBuffer` などは既定値のまま増やさない |
| キャッシュ用プロキシは非推奨                     | サーバー側でタイルを中継・保存するプロキシは作らない                                                     |
| 大量利用は予告なく遮断されうる。SLA（稼働保証）はない | 個人の自宅利用の範囲にとどめる。タイルが取得できなくても、軌跡（GeoJSON）・マーカー・ポップアップは表示できるようにする |
| 個人情報・機密データを OSMF に送らない           | 送るのはタイル座標のみ。GPS データ（CSV / GeoJSON）は外部に送信しない                                    |
| 「地図の誤りを報告」リンクの設置（推奨）         | 帰属表示に `https://www.openstreetmap.org/fixthemap` へのリンクを添える                                  |

- 上記ポリシーは予告なく変わることがあるため、実装時・運用中に定期的に確認する
- オフライン利用や先読みが必要になった場合は、OSMF のタイルではなく、自前のタイルサーバーや先読みを許可しているタイル提供元に切り替える（環境変数でタイル URL を差し替える）
- ライセンス表記は README の「ライセンス」節にまとめる

## 4. システム構成

```
[ブラウザ]
   │  ① CSV アップロード（Server Action）
   │  ② 一覧・トラック取得
   ▼
[Next.js サーバー（Node.js）]
   ├─ CSV 検証・変換（CSV → GeoJSON）
   ├─ SQLite（data/app.db）       … トラックのメタデータ
   └─ ファイル保存（data/）
        ├─ raw/{id}.csv           … アップロードされた元 CSV（再変換用）
        └─ tracks/{id}.geojson    … 変換済み GeoJSON（地図表示用）
```

- 既存の `m5-recorder/` と並べて、リポジトリ直下に `web/` ディレクトリを作成して実装する
- データ保存先は `web/data/`（環境変数 `DATA_DIR` で変更可能）とする

## 5. 機能要件

### W1: CSV アップロード

- 画面上部のアップロードボタンを押すとアップロードダイアログ（shadcn/ui の Dialog）を開く
- ダイアログでは次の 2 つを指定し、「アップロード」ボタンで送信する
  - **走行種別**（必須）: 「バイク」/「自転車」から選択する（shadcn/ui の RadioGroup または ToggleGroup）
    - 初期値は未選択とし、選択するまで「アップロード」ボタンを押せないようにする（選び忘れ防止）
  - **ファイル**（必須）: ファイル選択またはドラッグ&ドロップ
- 複数ファイルの同時選択に対応する（1 ファイルずつ順に処理し、結果を個別に通知）
  - 走行種別は同時に選択したすべてのファイルに適用する
- 受け付ける条件:
  - 拡張子 `.csv`
  - サイズ 10MB 以下（1 時間 ≒ 25KB のため、約 400 時間分に相当し十分）
  - 1 行目のヘッダーが `timestamp,latitude,longitude,altitude_m,speed_kmh,satellites,hdop` と一致する
  - 測位済みの行が 1 行以上ある
  - 走行種別が `motorcycle` / `bicycle` のいずれかである（サーバー側でも検証する）
- 同じ内容のファイル（SHA-256 ハッシュが一致）が既に登録済みの場合は、重複として登録しない
- 結果はトースト（Sonner）で通知する
  - 成功: 「20261011_012340.csv をバイクの走行として登録しました（2,243 点）」
  - 失敗: 理由を表示（形式不正 / 重複 / 測位データなし / サイズ超過）
- 登録に成功したら一覧を更新し、登録したトラックを選択状態にする

### W2: CSV → GeoJSON 変換

- アップロード時にサーバー側で変換し、元 CSV と変換後 GeoJSON の両方を保存する
- 変換ルール:
  - 測位済みの行（latitude / longitude が空でない行）を 1 点として扱う
  - 未測位の行（GPS データが空欄）は点にしないが、**軌跡の区切り**として扱う
    （未測位区間をまたいで直線で結ぶと誤った軌跡になるため、そこで線を分割する）
  - 数値として解釈できない行はスキップし、スキップ件数を記録する
- 変換時にメタデータ（6.2 の列）を算出して SQLite に保存する
  - 走行距離はハバーシン公式で隣接点間の距離を合計する（区切りをまたぐ区間は含めない）

### W3: トラック一覧（左ペイン）

- 登録済みトラックを**記録開始日時の新しい順**に表示する（アップロード日時ではない）
- 表示項目:
  - 走行種別（アイコン + バッジ。例: 🏍 バイク / 🚲 自転車）
  - 記録開始日時（JST 表示、例: `2026/10/11 13:51`）
  - 記録時間（例: `6時間16分`）
  - 走行距離（km、小数 1 桁）
  - 点数
- 行をクリックするとそのトラックを選択し、右ペインの地図に表示する
- 選択中の行はハイライトする
- 選択状態は URL のクエリ（`/?track={id}`）に保持し、リロードやブックマークで復元できるようにする
- トラックが 0 件の場合は「トラックがありません。CSV をアップロードしてください」と表示する

### W4: 地図表示（右ペイン）

- 選択したトラックの GeoJSON を取得し、軌跡をポリラインで表示する
- 軌跡の色は走行種別ごとの単色とする（速度などによるグラデーションは行わない）

  | 走行種別 | 軌跡の色 | 色の例                  |
  | -------- | -------- | ----------------------- |
  | バイク   | オレンジ | `#F97316`（orange-500） |
  | 自転車   | 青       | `#3B82F6`（blue-500）   |

  - 一覧の種別バッジ・サマリーの種別表示も同じ色を使い、色と種別の対応をそろえる
  - 色の定義は 1 か所（種別 → 色の対応表）にまとめ、ほかから参照する
- トラック選択時は軌跡全体が収まるよう自動でズーム・パンする
- スタート地点・ゴール地点にマーカーを表示する
- 軌跡上の点にマウスを合わせる（クリックする）と、その点の情報をポップアップ表示する
  - 日時（JST）、緯度・経度、高度、速度、衛星数、HDOP
- 地図右下に OpenStreetMap の帰属表示を常に表示する（3.4 参照）
- 背景タイルの取得に失敗しても、軌跡・マーカー・ポップアップは表示する
- 未選択時は「左の一覧からトラックを選択してください」と表示する
- 地図の上部（またはオーバーレイ）に選択中トラックのサマリーを表示する（帰属表示と重ならないよう右下には置かない）
  - 走行種別、開始〜終了日時、記録時間、走行距離、最高速度、平均速度

### W5: 時間スライダーによる再生

- 地図の下に再生コントロールを表示する（地図に重ねず、右下の帰属表示を隠さない）

  ```
  [▶] ──────●──────────────────────  15:32:10 / 20:07:12   速度: [60x ▼]
  ```

- スライダーの範囲は記録開始〜記録終了の時刻、1 目盛りは 1 レコード（10 秒）とする
  - 記録時間が 10 秒の倍数でないときは最大値を目盛りに切り上げ、最後の目盛りを記録終了の時刻として扱う
- スライダーを動かすと、その時刻の位置に**現在位置マーカー**を表示する
  - 現在位置マーカーの近くに日時（JST）・速度・高度を表示する
  - 開始〜現在位置までの軌跡は濃い色、未到達の軌跡は薄い色で表示し、進み具合を分かるようにする
- 再生ボタン（▶）を押すと、スライダーが自動で進み、現在位置マーカーが軌跡上を移動する
  - 再生中は一時停止ボタン（⏸）に切り替わる
  - 最後まで再生したら停止する。停止中に再生ボタンを押すと先頭から再生する
- 再生速度は実時間に対する倍率で選択する: `10x` / `60x`（既定）/ `300x` / `600x`
  - 例: 約 6 時間のサンプルは `60x` で約 6 分、`600x` で約 36 秒
- 点と点の間は補間せず、記録された点ごとにマーカーを移動する
- 未測位の区間に入ったときは、マーカーを最後に測位した位置に止め、「未測位」と表示する
- 現在位置マーカーが地図の表示範囲から外れたら、地図を自動で追従させる（パン）
  - 追従するのは再生中のみ。ユーザーが地図を手で動かしたら追従を止め、「追従を再開」ボタンを表示する
  - 追従のパンは表示中のタイル取得の範囲であり、先読みには当たらない（3.4 参照）
- トラックを切り替えたら、スライダーは先頭・停止状態に戻す
- 再生処理はブラウザ内だけで行い、サーバーへの追加のリクエストは発生しない（W4 で取得した GeoJSON を使う）

### W6: 走行種別の変更

- 登録済みトラックの走行種別を、後から「バイク」⇔「自転車」に変更できる
- 一覧の各行のメニュー（⋯）から「走行種別を変更」を選ぶと、変更ダイアログを表示する
  - 現在の種別を選択済みの状態で開き、別の種別を選んで「保存」を押すと変更する
  - 現在と同じ種別のままでは「保存」を押せない
- 変更したら一覧のバッジ・地図の軌跡の色・サマリーをすぐに反映する
- 結果はトーストで通知する（例: 「走行種別を自転車に変更しました」）
- 変更するのは SQLite の `activity_type` のみ（CSV・GeoJSON は種別を持たないため、再変換は不要）

### W7: トラック削除

- 一覧の各行のメニュー（⋯）から「削除」を選んで削除できる
- 確認ダイアログ（shadcn/ui の AlertDialog）を表示してから削除する
- 削除時は SQLite のレコード、`raw/` の CSV、`tracks/` の GeoJSON をすべて削除する

## 6. データ仕様

### 6.1 入力 CSV

M5 レコーダー仕様書「6. データ仕様」の形式に従う。

```csv
timestamp,latitude,longitude,altitude_m,speed_kmh,satellites,hdop
2026-10-11T01:23:40Z,35.658636,139.745407,12.3,42.5,9,0.9
2026-10-11T01:23:50Z,,,,,,
```

- 未測位区間が記録の末尾にある場合、その後に測位済みの行がないため軌跡の区切りにはならない
- 実際の走行データは位置情報（個人情報）を含むため、リポジトリ・ドキュメント・テストには含めない。例やテストの座標は東京タワー付近（35.658636, 139.745407）を使い、README のスクリーンショットは架空のルートのダミーデータ（`web/demo/`）で撮る
- タイムスタンプは UTC。表示時に JST（`Asia/Tokyo`）へ変換する

### 6.2 SQLite テーブル: `tracks`

| 列名              | 型      | 説明                                                  |
| ----------------- | ------- | ----------------------------------------------------- |
| id                | TEXT PK | トラック ID（UUID v4。並び順は `started_at` で決めるため時系列性は不要） |
| activity_type     | TEXT    | 走行種別。`motorcycle`（バイク）/ `bicycle`（自転車）。CHECK 制約で値を限定 |
| original_filename | TEXT    | アップロード時のファイル名（例: `20261011_012340.csv`） |
| content_hash      | TEXT    | 元 CSV の SHA-256（UNIQUE、重複判定用）               |
| started_at        | TEXT    | 最初の行の timestamp（ISO 8601 UTC）。一覧の並び順に使用 |
| ended_at          | TEXT    | 最後の行の timestamp（ISO 8601 UTC）                  |
| point_count       | INTEGER | 測位済みの点数                                        |
| no_fix_count      | INTEGER | 未測位の行数                                          |
| skipped_count     | INTEGER | 不正でスキップした行数                                |
| distance_m        | REAL    | 走行距離（m）                                         |
| max_speed_kmh     | REAL    | 最高速度（km/h）                                      |
| bbox              | TEXT    | 範囲 `[minLon, minLat, maxLon, maxLat]`（JSON 文字列）|
| uploaded_at       | TEXT    | アップロード日時（ISO 8601 UTC）                      |
| updated_at        | TEXT    | 最終更新日時（ISO 8601 UTC）。走行種別の変更時に更新  |

- インデックス: `started_at`（一覧は `ORDER BY started_at DESC` で取得）
- ファイルパスは `id` から決まるため DB には保存しない

### 6.3 変換後 GeoJSON

1 トラック = 1 FeatureCollection。未測位で区切られた連続区間ごとに LineString の Feature を 1 つ作る。

```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "geometry": {
        "type": "LineString",
        "coordinates": [[139.745407, 35.658636, 12.3], [139.746293, 35.659302, 12.6]]
      },
      "properties": {
        "segment": 0,
        "times": ["2026-10-11T01:23:40Z", "2026-10-11T01:23:50Z"],
        "speedsKmh": [42.5, 40.1],
        "satellites": [9, 9],
        "hdops": [0.9, 0.9]
      }
    }
  ]
}
```

- 座標は GeoJSON の規約どおり `[経度, 緯度, 高度]` の順（Leaflet は `[緯度, 経度]` なので表示時に入れ替える）
- 時系列の付帯情報は `coordinates` と同じ順・同じ長さの配列で `properties` に持つ
  （togeojson の `coordTimes` と同様の考え方。GPX 変換時もそのまま使える）
- 値が欠けている項目は `null` とする。ただし高度は座標の一部のため、高度がない点は `[経度, 緯度]` の 2 次元座標にする（GeoJSON の座標に `null` は使えないため）
- 点が 1 つしかない区間も LineString として保存する（表示時は点として描画）

### 6.4 GeoJSON を保存形式とする理由

- Leaflet / Google マップのどちらでもそのまま読み込める
- 時系列情報を `properties` に持たせられ、ポップアップ表示に使える
- GPX は地図ライブラリが標準で読めず、ブラウザ表示のためには再度変換が必要
- 他アプリ向けの GPX は、必要になったら GeoJSON（または元 CSV）からエクスポート機能として追加する

    ├── app.db

## 8. サーバー側インターフェース

| 種別          | 名前 / パス                     | 内容                                          |
| ------------- | ------------------------------- | --------------------------------------------- |
| Server Action | `uploadTrack(formData)`         | CSV と走行種別（`activityType`）を受け取り、検証・変換・保存して結果を返す |
| Server Action | `updateActivityType(id, activityType)` | トラックの走行種別を変更する（値はサーバー側でも検証） |
| Server Action | `deleteTrack(id)`               | トラックを削除する                            |
| Server Component | `/` ページ                   | DB から一覧を取得して描画                     |
| Route Handler | `GET /api/tracks/{id}/geojson`  | 変換済み GeoJSON を返す（地図コンポーネントから取得） |

- 地図（Leaflet）はブラウザ専用のため、Client Component として `dynamic(..., { ssr: false })` で読み込む
- アップロードの本体サイズ上限（Server Action の `experimental.serverActions.bodySizeLimit`）は 11MB とする（CSV の上限 10MB + multipart のオーバーヘッド。10MB の判定はアプリ側で行う）
- Cache Components が有効なため、DB（同期 API の better-sqlite3）を読むページの部分は `<Suspense>` で囲み、`connection()` でリクエスト時に読むことを明示する

## 9. 非機能要件

- **運用**: 自宅サーバー上で `next build`（`output: "standalone"`）した成果物を Node.js で起動する
  - 常駐化は systemd（または Docker Compose）。Docker の場合は `data/` をボリュームとしてマウントする
- **バックアップ**: `data/` ディレクトリをコピーするだけでバックアップできること
- **性能**: サンプル規模（約 2,000 点）のトラックを選択してから 1 秒以内に地図へ表示できること
  - 再生中もマーカーの移動がカクつかないこと（再生処理は `requestAnimationFrame` で行い、軌跡全体の再描画は避ける）
  - 数万点規模になった場合は、表示時の間引き（Douglas-Peucker など）を検討する
- **堅牢性**: 変換・保存の途中で失敗した場合、DB とファイルに中途半端な状態を残さない
  （ファイルを書き込んでから DB に登録し、DB 登録に失敗したらファイルを削除する）
- **セキュリティ**: 認証はないため、インターネットには公開しない（LAN 内のみ）
  - ファイル名はユーザー入力を使わず、サーバーで生成した `id` を使う（パストラバーサル対策）
- **外部サービスの利用**: 実行時に外部に通信するのはブラウザからの地図タイル取得（`tile.openstreetmap.org`）のみ。OSM タイル利用ポリシーを守る（3.4 参照）
  - フォント（Geist / Noto Sans JP）は `next/font` でビルド時に取得し、アプリから配信する（端末に日本語フォントがなくても表示がそろう）
